# 융합 정보를 전달하는 업그레이드 UI 조사

2026-10-30. 요청 범위: 디자인을 바로 그리지 않고, 스킬 선택과 융합 정보의 관계를 레퍼런스와 실제 프로젝트 규칙을 바탕으로 연구한다. 게임 코드와 에셋은 수정하지 않았다.

## 근거의 범위

- 현재 프로젝트의 스킬 획득·학습 레벨·장비 레벨·융합 재료 제거·전직 조건·후보 덱 추가 코드를 읽었다. 게임을 실행해 전체 흐름을 재현한 검증은 아니다.
- 새 참고 이미지 5장(4게임: Vampire Survivors, Magic Survival 2장, Backpack Battles, BALL x PIT)을 저장해 직접 열었다. Nova Drift는 이전 조사에서 직접 확인한 화면과 개발자 글을 다시 비교했다.
- TFT는 공식 개발 회고와 공식 UI 개선 패치 설명을 확인했다. 이번에 TFT의 실제 조작이나 최신 클라이언트 화면은 검증하지 않았다.
- Hades는 공식 Codex 기능 소개를 확인했다. 조건 상태 분류의 상세 비교에는 Hades II의 커뮤니티 모드 제작자 문서를 사용했으며, 원작 기본 기능으로 오인하지 않는다.
- 옛 버전의 화면은 정보 구조를 보는 자료다. 최신 수치·레시피·해금 레벨은 채택하지 않는다.
- 아래 UX 효과와 우리 게임 적용 방향은 설계 가설이며 사용자 테스트 결과가 아니다.

## 1. 프로젝트에서 확인한 규칙

### 즉시 획득, 조건 충족, 후보 추가는 서로 다른 사건

`UpgradeManager.OnUpgradeSelected`에서 선택한 카드의 Points를 증가시키고 무기 카드는 `AddWeapon`으로 적용한다. 이후 전직 조건을 반복 확인한다.

`CheckJobRequirements`는 MasterDeck의 업그레이드 Points와 JobRequirement.requiredLevel을 비교한다. `SetJob`의 bonusUpgrades는 UpgradeDeck에 카드를 넣거나 확률을 올린다. 이 경로는 새 스킬을 즉시 장착하는 것과 다르다.

따라서 코드에서 확인한 이 경로를 UI로 표현할 때는 다음을 구분해야 한다.

- 선택 직후 효과 증가
- 요구 조건에 한 단계 가까워짐
- 조건 충족과 전직/후보 해금
- 해금된 결과 스킬이 실제 제안으로 등장함
- 그 결과 스킬을 선택해 실제 획득함

조건 충족 시 `융합 완료`라고 쓰는 것은 이 경로에서는 부정확할 수 있다. `융합 스킬 해금`이나 `선택 후보에 추가`처럼 실제 결과에 맞춘 문구가 필요하다.

### 재료 스킬은 학습분이 제거된다

`PlayerWeaponController.AddWeapon(data)`는 `CheckFusion(data)`를 호출한다. 여기에 지정된 `fusionWeaponData` 각각에 `RemoveWeapon`이 실행되어 LearnedLevel이 0이 된다. 이후 결과 스킬 학습 레벨이 증가한다.

이 목록 자체에는 재료 요구 레벨이나 자동 해금 조건이 들어 있지 않다. `fusionWeaponData`만 읽고 '필요 조건 전체'라고 표시해서는 안 된다. 재료 제거 관계와 해금 조건을 별도로 다뤄야 한다.

### 장비 제공분과 학습분은 별개

학습분과 장비 제공분은 따로 관리된다. `RemoveWeapon`은 학습분만 지우므로 장비분이 있으면 재료 스킬의 효과가 남을 수 있다. 장비 획득 경로는 융합 재료 제거를 호출하지 않는다.

따라서 `아이콘이 켜져 있다 = 융합 조건 만족`, `재료로 사용 = 무조건 완전히 사라짐` 같은 단순한 표시는 위험하다. 실제 조건 평가에 쓰는 Points, 학습 레벨, 장비 레벨을 혼동하지 않는다.

### 데이터 사례

- W_Turret Fire Trail Orb는 재료 스킬 2개를 지정한다: 포탑 데이터와 Fire Trail Orb 데이터.
- W_ArcFireball은 재료 스킬 1개를 지정한다. 모든 변화가 반드시 A+B인 것은 아니다.
- J_Celestial은 두 업그레이드의 Points가 각각 5 이상인 조건을 갖고, 보너스 후보 업그레이드를 지정한다.

위는 에셋/코드 확인 사실이다. 실제 화면에 표시할 한국어 이름과 플레이 중 도달 경로까지 확정한 것은 아니다.

## 2. 레퍼런스별 배울 점

### Vampire Survivors — 압축된 조합식과 전체 목록

직접 확인한 Grimoire 화면은 작은 아이콘으로 A+B=결과를 여러 줄 나열한다. 일부 요소에 배경 강조가 있다. 화면만으로 강조색의 모든 규칙까지 단정하지 않는다.

배울 점: 학습한 아이콘으로 관계를 짧게 표현할 수 있다. 전체 조합을 정리하는 도감에 적합한 형식이다.

우리 게임에 적용할 가설: 카드에는 관련 결과가 있다는 표시만 두고, 자세한 조합식을 별도 영역에서 볼 수 있게 한다. 다만 아이콘만으로는 요구 레벨·재료 유지 여부·자동 발동 여부가 설명되지 않는다.

### Magic Survival — 강화 결과와 잃는 기능을 함께 설명

직접 확인한 과거 Winter Storm 화면은 결과 이름과 장면 미리보기, Fireball 사용 불가 문구, 증가 효과와 감소 효과, Learn 액션을 담고 있다. v0.86 안내 화면은 재료 마법을 소비하는 조합 개념을 설명한다.

배울 점: 결과의 이점만 강조하지 않고 재료 기능의 손실도 획득 전에 표현한다. 우리 게임의 재료 학습분 제거와 가까운 참고다.

적용 가설: 결과 설명 바로 옆에서 '대체되는 학습 스킬'을 읽게 한다. 장비분이 유지될 경우는 실제 효과에 맞게 별도로 설명한다. 과거 버전의 조합 슬롯이나 레벨 제한은 우리 게임에 이식하지 않는다.

### Backpack Battles — 결과 설명과 재료 설명을 분리해서 연결

적용 가설: 스킬에서 앞으로 만들 결과를 탐색하는 방향과, 결과에서 필요한 재료를 확인하는 방향을 모두 제공한다. 다중 툴팁이 화면을 가릴 수 있어 고정된 상세 패널 방식도 비교한다.

### TFT — 현재 재료에서 출발하는 결과 탐색

공식 개발 회고는 재료를 우클릭해 그 재료로 만들 결과를 보여주는 recipe hints 도입을 설명한다. 공식 11.11 패치는 표시된 결과를 다시 호버/탭해 완성품 효과를 읽도록 확장했다.

배울 점: 사용자가 지금 보고 있는 재료를 출발점으로 삼는다. 전체 조합표를 먼저 외울 필요가 줄어드는 설계다.

적용 가설: 우리 게임은 최소한 '준비 중 / 조건 충족·해금 / 실제 융합 획득'을 구분한다. 현재 직업 경로상 불가능한 결과는 단순 레벨 부족과 다른 이유를 표시한다. 색만으로 구분하지 않는다.

### BALL x PIT — 결과와 재료를 같은 선택 단위에서 표현

배울 점: 결과 아이콘만 나열하지 않고 조합의 출처를 같은 단위에 묶을 수 있다. 같은 결과에 여러 재료 조합이 있다면 서로 대안인 레시피를 '모두 필요'로 보이게 하지 않아야 한다.

적용 가설: 결과별 상세에서 대체 레시피를 행으로 나누고 '또는' 관계를 명확히 한다. 현재 프로젝트에 대체 레시피가 실제 구현됐다고 가정하지 않는다.

## 3. 설계해야 할 정보는 세 종류

### A. 지금 고르는 스킬의 효과

이번 선택의 직접 효과, 현재 레벨에서 선택 후 레벨, 새로 배우는지 여부. 융합 예고 때문에 이 정보가 밀려나지 않는다.

### B. 이 선택이 미래 융합에 주는 기여

관련 결과의 이름/아이콘, 다른 재료, 요구 레벨, 현재 충족 상태, 이번 선택을 반영한 상태. '레벨 4/5 → 5/5'처럼 선택 후 변화를 보여준다.

### C. 실제 결과 스킬을 얻을 때의 변화

결과의 작동 방식과 수치, 대체되는 학습 스킬, 남는 장비 제공 효과, 슬롯/효과 변화(규칙 확인 후), 다른 경로의 가능 여부. UI에서 약속하는 내용은 실제 규칙과 일치해야 한다.

## 4. 아직 그림으로 고정하지 않을 구조 가설

공통 원칙은 정보의 단계적 공개다. 아래는 확정안이 아닌 비교 후보다.

1. **후보 안의 작은 표시 + 공용 융합 상세**: 각 후보에는 관련 결과 수/가까운 결과만 표시. 포커스한 후보의 레시피를 한 상세 영역에 표시한다.
2. **목록 + 융합 측면 패널**: 짧은 선택 목록 한쪽에 관련 결과 목록, 나머지 조건, 선택 후 진행을 표시한다.
3. **아이콘 선택 + 아래 두 영역**: 직접 효과와 미래 융합을 별도 제목으로 구분한다. 필요한 만큼만 높이가 늘어나게 한다.
4. **목표 추적 영역**: 플레이어가 정한 융합 목표 하나와 이번 선택의 기여를 보여주고, 관련 없는 모든 조합은 펼치지 않는다. 목표 고정은 신규 기능 제안이다.
5. **실제 융합 후보만 확장 표시**: 일반 강화는 작게, 실제 재료 제거가 발생하는 결과 후보는 재료→결과 관계와 대체 설명을 넓게 표시한다.

어느 구조든 스킬 A에서 결과들을 찾는 정방향 정보와, 결과 C에서 재료를 찾는 역방향 정보가 필요하다. 외형보다 관계 탐색이 먼저다.

## 5. 표시 상태와 문구의 구분

| 상황 | 적합한 정보 | 피할 표현 |
|---|---|---|
| 재료를 아직 안 배움 | 재료 미보유 / 필요한 스킬 | 이유 없는 회색 잠금 |
| 재료는 있지만 조건 레벨 부족 | 현재/요구 레벨, 이번 선택 후 진행 | 보유만으로 충족 표시 |
| 조건을 채워 후보에 추가됨 | 해금 / 후보에 추가 | 융합 완료, 즉시 획득 |
| 이번 선택이 결과 스킬 자체 | 획득 결과와 대체되는 학습 스킬 | 미래 경로와 같은 배지 |
| 장비로만 제공되는 재료 | 장비 제공, 학습 조건 별도 | 아이콘 활성만으로 재료 충족 |
| 직업 경로상 현재 도달 불가 | 접근 제한 이유(실제 규칙 확인) | 레벨 부족과 같은 표시 |
| 정보가 미발견 | 미발견 결과 / 알려진 조건의 범위 | 미보유·접근 불가와 혼동 |

미발견 정보의 공개 범위는 아직 사용자가 정하지 않았고 코드에서도 이 조사로 확인하지 못했다. 스포일러 정책을 임의 확정하지 않는다.

## 6. 한 스킬의 융합 결과가 많아질 때

- 결과 1개만 있는 예시로 검증하지 않는다. 0개, 1개, 3개, 8개를 시험한다.
- 기본 화면에 모두 펼치기보다 관련 결과 수와 대표 항목, 전체 보기의 조합을 비교한다.
- 현재 경로에서 도달 가능, 이번 선택으로 새로 해금, 부족 조건이 적은 순서 등을 정렬 후보로 둔다. 무조건 고등급 먼저로 고정하지 않는다.
- 선택 전 상태와 선택 후 예상 상태는 실제 데이터를 바꾸지 않고 계산해야 한다.
- 결과 아이콘을 호버한 순간 설명이 사라지는 중첩 툴팁은 피하고, 필요하면 상세 고정/포커스 전환을 지원한다.
- 색은 등급과 조건 충족을 동시에 뜻하게 하지 않는다. 체크·자물쇠·현재/요구 숫자·문구를 함께 사용한다.

## 7. 앞선 20개 초안을 재평가하는 기준

- 05 현재 빌드 연결: 재료 자격, 실제 대체 여부를 표시할 공간이 있다. 현재 빌드 아이콘이 재료 충족을 잘못 뜻하지 않도록 구분이 필요하다.
- 06 성장 분기, 19 별자리 빌드: 관계를 드러내지만 작은 화면에서 복잡해질 수 있다. 해금과 획득이 섞여 보일 수 있다.
- 08 마도서, 11 측면 목록: 선택 목록과 융합 상세를 나누기 쉽다. 게임 화면 점유와 긴 조건 목록을 검토해야 한다.
- 03 룬 선택, 17 마름모 슬롯: 기본 선택은 간단하지만 공용 설명창을 직접 효과/융합 조건으로 확장해야 한다.
- 01 짧은 목록, 02 낮은 타일, 16 무테 구성: 융합 없는 일반 강화에는 가볍다. 결과 여러 개를 모두 같은 자리에서 보여주기에는 부족하므로 상세 접근이 필요하다.
- 20 세로 카드: 작은 레시피 하나는 넣기 쉽지만 결과 개수에 따라 카드 높이와 밀도가 크게 달라진다.

이 평가는 최종 후보를 고른 것이 아니다. 이번 요구가 들어왔으므로 20개 외형의 미감만으로 순위를 정하면 안 된다는 의미다.

## 8. 시안 전에 검증할 사례

1. 기본 재료 A 신규 획득: 관련 융합 없음 / 1개 / 다수.
2. A만 충족, B는 미보유.
3. A 4/5, B 5/5에서 이번 선택으로 A 조건 충족.
4. 조건 충족했지만 결과 스킬은 아직 후보 덱에만 있음.
5. 결과 스킬 제안을 선택하면 A와 B의 학습분이 제거됨.
6. B의 학습분과 장비분을 동시에 보유해 장비 효과가 남음.
7. 재료 1개인 대체, 재료 2개인 융합, 추가 조건이 있는 해금.
8. 한 결과에 대체 레시피가 존재하는 가정(실제 지원 여부 미확정).
9. 현재 직업 분기에서 접근 불가능하거나 중간 단계를 거치는 결과.
10. 최장 한국어 이름/설명과 패드·터치의 상세 탐색.

## 결론

다음 시안의 핵심은 '업그레이드 설명에 융합 아이콘을 몇 개 추가'하는 것이 아니다. 현재 후보에서 관련 결과를 찾고, 선택 후 조건 변화를 비교하고, 실제 융합 획득 때 대체되는 기능을 확인하는 탐색 흐름을 설계해야 한다. 작은 예고와 자세한 레시피의 층을 나누는 방향을 먼저 검증하되, 아직 특정 외형으로 확정하지 않는다.
