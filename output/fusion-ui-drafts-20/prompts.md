Built-in image generation, 2026-10-30. Layout explorations; not production sprites or validated game state screenshots.

## Limitations

Skill names and numbers are illustrative. Some generated labels mix pre-pick and post-pick levels, offer max-level ingredients, or repeat information. Compare layout, not exact state correctness. Final UI must use project rules. Concepts 17, 18, 20 depict actual acquisition; the others depict future unlock/progression information.

## Shared prompt

Create ONE landscape 16:9 in-game UI CONCEPT DRAFT for Korean pixel-art fantasy survivor roguelike, with fusion information as essential readable gameplay information. This is ONE of 20 independently designed alternatives. Use very dim top-down dungeon battlefield, restrained crisp pixel-art UI corners and icons, bitmap-inspired readable Korean type, flat limited palette, no glassmorphism, no photorealism, no blurry bloom, no parchment unless expressly requested. Avoid excessive ornament and giant illustrations. Same EXAMPLE CONTENT for consistent comparison: normal upgrade choices '화염탄' (level 'Lv.4 → Lv.5', benefit '피해량 +20%'), '궤도 화염' and '최대 체력'. Fictional fusion recipe: '화염탄 Lv.5' plus '궤도 화염 Lv.5' unlocks '융합 화염포'. Current selected normal upgrade changes fireball condition from '4/5 → 5/5'; orbit is already '5/5'. For NORMAL UPGRADE concepts explicitly show '이번 선택으로 해금' and tiny '선택 후보에 추가' near output: requirements completed does NOT mean instant acquisition. For concepts explicitly marked ACTUAL FUSION ACQUISITION STATE, instead show actual merging/replacement and '융합 획득', no future unlock statement. Always keep direct upgrade effect distinct from future fusion contribution. Requirement state uses ticks/numbers as well as color; don't confuse rarity with readiness. Korean concise exact labels '융합 조건', '보유', '부족' where useful. Tiny reroll '다시 뽑기 · 2회'. Small concept number top-left.
